**适用项目：** `rl_admittance_rehab_ws`
**当前实现：** Phase 0–10
**建议读者：** 了解一点 Python，但刚开始接触 MuJoCo、导纳控制、Gymnasium、强化学习和 ROS2 的同学

## 0. 先理解这是什么项目

这个项目不是“让强化学习直接控制电机”的项目，而是一个分层的安全实验系统：

```text
MuJoCo 三自由度机器人 + 虚拟患者
              │
              ▼
      任务空间导纳控制器
              │
              ▼
        IK 关节目标映射
              │
              ▼
          MuJoCo 仿真机器人

观测 ──► SAC / PPO / 规则策略 ──► 导纳参数增量
                         │
                         ▼
             独立安全投影与故障回退

遥测 ──► 交互 Agent（只读）──► 文字反馈/事件日志
```

项目的核心思想是：

1. 机器人底层运动和导纳控制由确定性程序完成。
2. 患者模型产生交互力，模拟不同能力、延迟、噪声、震颤和疲劳。
3. 强化学习只在较低频率上调整阻尼、辅助增益和速度比例。
4. 所有策略输出都必须经过参数边界、变化率和状态安全检查。
5. Agent 只解释训练状态，不修改控制参数，也不发布机器人命令。

因此，这个项目适合学习“安全约束下的机器人强化学习系统如何分层构建”，也适合用作仿真型求职项目。当前参数仍是仿真占位值，不能直接用于真实机器人或人体训练。

## 1. 学习前需要知道的概念

### 1.1 平面三自由度机器人

机器人有三个转动关节，三个关节轴都沿 MuJoCo 的 `+Z` 方向，因此机械臂在 XY 平面内运动。任务空间状态写成：

```text
X = [x, y, theta]
```

其中：

- `x`：末端在 X 方向的位置，单位 m；
- `y`：末端在 Y 方向的位置，单位 m；
- `theta`：末端平面姿态，单位 rad。

人机交互信号写成：

```text
F = [Fx, Fy, Tz]
```

其中 `Fx`、`Fy` 是末端平面内的力，`Tz` 是绕 Z 轴的力矩。

本项目已经把 CAD 导入的零位校正为“三个连杆在一条直线上”。在环境重置时，关节角从零开始，便于理解和复现实验。

### 1.2 导纳控制是什么

导纳控制把外力转换成机器人期望运动。项目使用对角三自由度模型：

```text
M * X_ddot + D * X_dot + K * (X - X_ref)
    = F_effective + F_assist
```

可以把它理解成一个“虚拟的质量—阻尼—弹簧系统”：

- `M` 越大，机器人对力的响应越迟钝；
- `D` 越大，动作越平滑、越不容易振荡，但也可能变得僵硬；
- `K` 越大，机器人越倾向于回到参考轨迹；
- `F_assist` 是辅助力，辅助增益越大，机器人越主动帮助患者。

项目中的导纳控制器还包含：力低通滤波、软死区、速度限幅、加速度限幅和工作空间裁剪。

### 1.3 强化学习在这里做什么

强化学习策略每隔一段时间观察系统状态，然后输出四维动作：

```text
a = [dDxy, dDtheta, dKa, dlambda_v]
```

它们分别代表：

- `dDxy`：同时调整 X/Y 平面阻尼；
- `dDtheta`：调整姿态阻尼；
- `dKa`：调整辅助增益；
- `dlambda_v`：调整速度比例。

在 Gymnasium 环境中，这四个动作都限制在 `[-1, 1]`。动作不是关节力矩，也不是电机电流。以当前配置为例，动作会按以下尺度影响参数：

```text
D_x, D_y       += dDxy      * 0.25
D_theta        += dDtheta   * 0.02
K_assist       += dKa       * 0.50
lambda_v       += dlambda_v * 0.05
```

之后还会投影到参数边界内。

### 1.4 交互 Agent 做什么

Phase 8 的 Agent 是规则式 Agent，不依赖大语言模型和外部 API。它读取跟踪误差、交互力、速度、患者主动功率、疲劳和安全状态，然后生成：

- 训练开始提示；
- 跟踪良好提示；
- 跟踪误差过大提示；
- 交互力过大提示；
- 速度过快或过慢提示；
- 患者主动做功不足提示；
- 疲劳或安全停止提示；
- 训练结束总结。

它不能改导纳参数，不能调用电机，不能绕过安全层。未来如果接入 DeepSeek 等 LLM，也只能让 LLM 生成解释、总结或语音文案，不能让它进入控制闭环。

## 2. 第一次运行：从零开始安装

### 2.1 进入正确目录

所有命令都建议在项目工作区根目录执行：

```bash
cd rl_admittance_rehab_ws
```

如果你使用的是本机绝对路径，可以写成：

```bash
cd /home/jack/Desktop/RL/ROBOT/rl_admittance_rehab_ws
```

### 2.2 创建 Python 虚拟环境

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install -r requirements.txt
python3 -m pip install -e .
```

`requirements.txt` 中包含项目主要依赖：

- `numpy`：数值计算；
- `mujoco`：物理仿真；
- `gymnasium`：强化学习环境接口；
- `stable-baselines3`：SAC/PPO 实现；
- `pyyaml`：加载 YAML 配置；
- `matplotlib`、`imageio`、`imageio-ffmpeg`：图表和视频；
- `pytest`、`ruff`、`mypy`：测试、格式和类型检查。

### 2.3 第一次自检

```bash
python3 -m scripts.check_config
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q
ruff check .
ruff format --check .
mypy rehab_sim scripts
```

如果看到 `57 passed`，说明当前 Python 代码测试通过。测试环境若没有 ROS2，ROS2 接口测试可能会被跳过；这不代表 ROS2 节点已经验证。

### 2.4 为什么要使用 `python3 -m scripts.xxx`

推荐这样运行：

```bash
python3 -m scripts.run_phase10_experiments --quick
```

而不是：

```bash
python3 scripts/run_phase10_experiments.py --quick
```

项目脚本依赖工作区根目录下的 `rehab_sim` 包。使用模块形式运行，Python 会正确把项目根目录加入导入路径，最不容易遇到 `ModuleNotFoundError: No module named 'rehab_sim'`。

## 4. Phase 1：机器人模型和 MuJoCo

### 4.1 机器人配置

先看 `configs/robot.yaml`：

```yaml
robot:
  dof: 3
  task_space: [x, y, theta]
  interaction_wrench: [Fx, Fy, Tz]
  joint_names: [joint1, joint2, joint3]
  end_effector_site: tool_tip
```

这个文件是“系统对机器人怎么理解”的入口。它规定自由度、关节名、末端 site 名称和任务空间变量。

几何参数来自 CAD 导入和网格包络估计。需要特别注意：`tool_offset_m` 目前标记为需要硬件验证，真实机器人使用前必须重新测量末端工具偏置。

### 4.2 零位为什么是三连杆共线

环境 reset 时使用零关节角：

```python
self.robot.reset(np.zeros(3), np.zeros(3))
```

同时，配置中的 CAD 偏移已按零位共线关系修正。因此新手调试时可以先假设：

```text
q = [0, 0, 0]
```

对应三根连杆沿同一方向展开。若你修改了 MuJoCo XML 的关节初始角、几何 offset 或 link frame，必须重新检查零位，不能只改 YAML。

### 4.3 运行 MuJoCo

无头运行适合测试，不弹出窗口：

```bash
python3 -m scripts.run_phase1_sim --headless --steps 1000
```

可视化运行：

```bash
python3 -m scripts.run_phase1_sim --top
```

施加末端恒定外力：

```bash
python3 -m scripts.run_phase1_sim \
  --headless --steps 1000 --wrench 0.5 -0.2 0.1
```

这里的外力只是数字孪生测试接口，不等于真实力传感器，也不等于导纳控制已经连接到电机。

### 4.4 MuJoCo 中“机器人乱动”怎么排查

按以下顺序排查：

1. 先用 `--headless` 加 `--steps 1000`，排除窗口操作干扰。
2. 使用固定参数模式或零动作，不要一开始就运行随机 RL 策略。
3. 检查 `configs/admittance.yaml` 的速度、加速度和阻尼范围。
4. 检查动作是否被限制在 `[-1, 1]`。
5. 检查 `configs/safety.yaml` 中的参数边界和回退参数。
6. 检查是否在每个 episode 开始调用了 `reset()`。
7. 检查 `q=[0,0,0]` 是否仍对应三连杆共线零位。

强化学习早期策略通常是随机的，直接观察它会觉得机器人“乱动”。正确做法是先用固定导纳建立稳定基线，再逐步启用规则策略、SAC/PPO 和安全监督器。

## 5. Phase 2：固定参数导纳控制器

### 5.1 控制器内部发生了什么

`rehab_sim/controllers/admittance_controller.py` 的一次更新大致是：

1. 读取当前末端位姿、参考位姿和交互力。
2. 对交互力做一阶低通滤波。
3. 对小力做软死区处理，避免噪声导致运动。
4. 根据导纳方程计算任务空间加速度。
5. 限制加速度和速度。
6. 积分得到期望位姿。
7. 将期望位姿裁剪到工作空间。
8. 由阻尼最小二乘 IK 转换为关节目标。

控制器只输出期望任务位姿、速度和加速度，不直接写电机力矩。

### 5.2 查看基线参数

```bash
sed -n '1,180p' configs/admittance.yaml
```

当前仿真基线中：

- `damping.x/y = 3.0`；
- `damping.theta = 0.25`；
- `assist_gain = 0.0`；
- `velocity_scale = 1.0`。

这些值是仿真占位参数，不能直接被解释为真实机器人安全参数。

### 5.3 运行三个基线实验

```bash
python3 -m scripts.run_phase2_baseline --experiment step --duration 3
python3 -m scripts.run_phase2_baseline --experiment sine --duration 3
python3 -m scripts.run_phase2_baseline --experiment reverse --duration 3
```

输出在 `experiments/reports/phase2_baseline/`，包括：

- CSV：每个时间点的力、位姿、速度、加速度和关节目标；
- SVG：力、速度和位置曲线；
- JSON：峰值、漂移和样本数摘要。

新手建议先修改一个参数，例如把 `damping.x` 从 `3.0` 改为 `6.0`，然后重新跑 `step` 实验，观察动作变慢、波动变化和跟踪误差变化。

## 6. Phase 3：虚拟患者模型

### 6.1 患者力模型

虚拟患者不是人体生理仿真，而是为了让训练环境产生可控、可重复的人机交互力。核心形式为：

```text
F_h = K_h * (X_delayed - X)
    + D_h * (Xdot_delayed - Xdot)
    + F_bias + F_noise + F_tremor
```

组成部分：

- 阻抗项：患者试图跟随目标；
- 反应延迟：患者不是瞬时响应；
- 方向偏置：模拟偏向某个方向；
- 高斯噪声：模拟测量和动作波动；
- 震颤：模拟周期性小幅振动；
- 疲劳：主动做功越多，疲劳越高。

### 6.2 三种患者

| 患者 | strength | delay | noise/tremor | fatigue rate | 直观含义 |
| --- | ---: | ---: | ---: | ---: | --- |
| mild | 0.90 | 40 ms | 小 | 0.02 | 能力较好、响应快 |
| moderate | 0.60 | 150 ms | 中 | 0.04 | 中等能力，默认训练患者 |
| severe | 0.30 | 280 ms | 大 | 0.06 | 能力较弱、延迟大、易疲劳 |

配置在 `configs/patient_profiles.yaml`。演示：

```bash
python3 -m scripts.run_phase3_patient_demo --duration 8 --sample-time 0.01
```

### 6.3 为什么需要多个患者

如果只在一个患者模型上训练，策略可能只是记住这个患者的动力学。轻度、中度、重度测试可以检查：

- 跟踪能力是否变化合理；
- 辅助是否过强；
- 交互力是否接近仿真阈值；
- 患者主动功率和疲劳是否有变化；
- 策略是否只适用于一个固定条件。

## 7. Phase 4：Gymnasium 环境

### 7.1 三种任务

环境支持：

1. `point_to_point`：从当前点移动到目标点；
2. `circle_tracking`：沿圆轨迹跟踪；
3. `figure8_tracking`：沿八字轨迹跟踪。

任务参数位于 `configs/tasks.yaml`，包括距离、半径、参考速度、容差和任务时长。

### 7.2 观测空间

环境返回一个字典观测，主要字段是：

```text
joint_position          关节位置
joint_velocity          关节速度
end_effector_pose       末端 [x,y,theta]
end_effector_velocity   末端速度
interaction_force       交互 [Fx,Fy,Tz]
reference_pose          参考 [x,y,theta]
tracking_error          参考 - 实际
admittance_parameters   [Dx,Dy,Dtheta,Ka,lambda_v]
task_progress           任务进度
safety_status           仿真安全状态
```

使用结构化观测是为了让 SB3 的 `MultiInputPolicy` 可以分别处理不同物理含义的信号。

### 7.3 `step()` 一次做什么

一次 Gymnasium `step(action)` 会：

1. 把四维动作裁剪到 `[-1,1]`。
2. 更新导纳参数。
3. 在一个低频动作间隔内运行多次 MuJoCo 物理步。
4. 让患者产生交互力。
5. 更新导纳控制器。
6. 使用 IK 生成关节目标。
7. 将外力施加到 MuJoCo 末端并推进仿真。
8. 累积跟踪误差、交互力、患者主动功率和辅助能量。
9. 计算奖励，并判断成功、超时或不安全终止。

### 7.4 奖励函数

奖励不是只有“到达目标”这一项，而是分项组合：

```text
奖励 = 进度奖励
     - 跟踪误差惩罚
     - 过大交互力惩罚
     - 运动突变/jerk 惩罚
     - 机器人辅助能量惩罚
     - 参数变化惩罚
     + 患者主动功率奖励
     + 成功奖励
     - 不安全终止惩罚
```

每一项都会记录在 `info["reward_components"]` 中。调奖励时不要只看总 reward，要同时看这些分项，否则可能出现“总 reward 上升但交互力也上升”的情况。

### 7.5 运行环境检查

```bash
python3 -m scripts.check_phase4_envs
```

也可以只运行环境测试：

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q tests/unit/test_sac_evaluation.py
```

## 8. Phase 5：SAC 强化学习

### 8.1 SAC 的直观理解

SAC 是适合连续动作空间的 off-policy 算法。它有三个重要特点：

- 使用 replay buffer 保存历史交互；
- 学习 actor 和 critic；
- 在奖励之外加入熵项，鼓励适度探索。

在本项目中，SAC 的动作不是关节角或关节力矩，而是四维导纳参数增量。

### 8.2 SAC 的训练配置

主要配置在 `configs/rl_sac.yaml`：

```yaml
algorithm: SAC
training:
  total_timesteps: 20000
  random_seeds: [0, 1, 2, 3, 4]
  parameter_update_hz: 5.0
normalization:
  enabled: true
  normalize_observation: true
  normalize_reward: true
```

注意 `total_timesteps: 20000` 是项目配置中的短周期仿真占位值。研究训练通常需要更多步数，并且需要重新设计训练预算、评估频率和统计方法。

### 8.3 训练 SAC

按配置训练：

```bash
python3 -m scripts.train_sac
```

快速 smoke run：

```bash
python3 -m scripts.train_sac \
  --run-name smoke \
  --total-timesteps 2000 \
  --seeds 0 \
  --learning-starts 256 \
  --device cpu
```

训练结果会保存模型、归一化统计、checkpoint、TensorBoard event 和评估历史。加载模型评估：

```bash
python3 -m scripts.evaluate_sac \
  --model experiments/trained_models/phase5_sac/<run>/seed_0000/final_model.zip \
  --vecnormalize experiments/trained_models/phase5_sac/<run>/seed_0000/vecnormalize.pkl
```

`<run>` 要替换成实际生成的实验目录名。

### 8.4 为什么必须保存 VecNormalize

训练时观测和 reward 被归一化。如果评估时不加载同一份 `vecnormalize.pkl`，模型看到的数值分布会改变，结果可能明显失真。因此：

```text
model.zip + vecnormalize.pkl
```

应作为一个整体保存和使用。

## 9. Phase 6：安全层怎么工作

### 9.1 安全层与 RL 解耦

安全代码位于 `rehab_sim/safety/`，不依赖 Stable-Baselines3。这样即使 RL 模型加载失败，安全层也可以独立运行。

部署时的数据流是：

```text
策略原始动作
  -> NaN/形状检查
  -> 动作裁剪
  -> 参数变化率限制
  -> 参数边界投影
  -> 力/力矩/速度/加速度检查
  -> 通过：使用安全参数
  -> 失败：切换固定回退参数
```

### 9.2 当前配置的安全参数

`configs/safety.yaml` 中包括：

- 交互力和交互力矩阈值；
- 任务空间速度和加速度阈值；
- 导纳参数上下界；
- 每次更新的参数变化率；
- 策略推理超时；
- 保守固定回退参数。

所有值都注明 `simulation_only` 或 `hardware_validation_required`。不要把仿真阈值直接写进真实机器人控制器。

### 9.3 什么情况会触发回退

常见触发原因：

- 模型文件不存在或加载失败；
- 推理抛出异常；
- 推理时间超过上限；
- 动作或传感器状态出现 NaN/Inf；
- 交互力、力矩、速度或加速度超限；
- 传感器掉线；
- 参数投影失败。

回退不是“让 RL 再试一次”，而是立即使用配置中的固定安全参数。

### 9.4 运行安全测试

```bash
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest -q tests/unit/test_safety.py
```

新手修改安全代码后，至少要测试：正常动作、超界动作、NaN 动作、模型未加载、传感器掉线、力超限和推理超时。

## 10. 五种方法到底怎么用

Phase 10 的统一入口会用同一个任务、同一个环境和同一个四维动作接口比较五种方法。

### 10.1 固定导纳：`fixed_admittance`

它的动作始终是：

```text
[0, 0, 0, 0]
```

因此导纳参数保持 `configs/admittance.yaml` 中的基线值。它的用途不是追求最好成绩，而是作为“没有自适应”的参考。

适合用来回答：

- 任何自适应策略是否真的改善了结果？
- RL 的改进是否只是随机波动？
- 患者变重后，固定参数是否明显退化？

### 10.2 规则自适应：`rule_adaptive`

这是一个可解释的确定性策略。它读取：

- 平面交互力大小；
- 平面跟踪误差；
- 姿态误差；
- 末端速度。

概念公式为：

```text
force_delta = ||F_xy|| - force_reference
a0 = damping_gain * force_delta
a1 = theta_gain * |error_theta|
a2 = assist_gain * ||error_xy||
a3 = -velocity_gain * ||velocity||
```

所有动作最后都会裁剪到 `[-1,1]`。参数在 `configs/phase10.yaml` 的 `policies.rule_adaptive` 中。

它的优点是容易解释、容易调参、容易定位问题。它的缺点是规则是人写的，面对复杂患者可能不够灵活。

### 10.3 模糊规则：`fuzzy_control`

模糊策略先把力、误差和速度变成 0 到 1 的“高程度”：

```text
force_high = ramp(||F_xy||, force_low, force_high)
error_high = ramp(||error_xy||, error_low, error_high)
speed_high = ramp(||velocity||, speed_low, speed_high)
```

然后组合规则：

```text
damping = w_force * force_high + w_speed * speed_high
assist  = w_error * error_high * (1 - 0.5 * force_high)
velocity = -w_velocity * speed_high
```

直观上：误差大时可以增加辅助，力或速度大时增加阻尼并降低速度；如果交互力已经大，辅助不会无限增加。

它比硬阈值规则更平滑，但依然不是真正学习出来的策略。

### 10.4 SAC：`sac`

Phase 10 会实际创建 SB3 SAC 模型，使用 `MultiInputPolicy` 读取结构化观测，训练结束后在轻度、中度、重度患者上做确定性评估。

SAC 的使用流程：

1. 从 `configs/rl_sac.yaml` 读取环境、动作和 reward 配置；
2. 在 `training.patient_profile` 指定的患者上训练；
3. 保存 `sac_seed_XXXX.zip` 和 VecNormalize 文件；
4. 复制训练时的归一化统计到评估环境；
5. 用 `deterministic=True` 评估三类患者。

SAC 适合探索复杂的阻尼—辅助—速度权衡，但训练成本高、可解释性弱，需要更多随机种子和独立测试。

### 10.5 PPO：`ppo`

PPO 是 on-policy 连续控制算法，通过限制新旧策略更新幅度，避免一次更新过大。Phase 10 使用相同观测、相同动作接口和相同任务环境创建 PPO 模型，再按确定性方式评估。

PPO 的基本流程：

1. 用当前策略采样一批轨迹；
2. 计算优势函数；
3. 使用裁剪目标更新策略；
4. 更新价值函数；
5. 重复采样和更新。

PPO 与 SAC 的重点差异：

| 对比项 | SAC | PPO |
| --- | --- | --- |
| 数据 | off-policy，可重复利用 replay buffer | on-policy，主要使用当前策略数据 |
| 探索 | 熵正则化 | 通过策略分布和更新过程探索 |
| 连续动作 | 很适合 | 也适合 |
| 工程关注点 | buffer、学习起始步数、归一化 | rollout 长度、batch size、clip range |
| 本项目用途 | 学习自适应导纳参数 | 与 SAC 做算法对比 |

### 10.6 五种方法的公平比较原则

比较时必须尽量保持以下条件相同：

- 相同任务；
- 相同患者 profile；
- 相同 episode 数量；
- 明确记录随机种子；
- 相同成功判据和不安全终止判据；
- 统一统计成功率、误差、力、能量和参数稳定性。

不能只比较某一次 reward，也不能只挑选对某种方法最有利的患者。

### 11.3 页面里的“控制”应该怎么理解

页面里的控制按钮控制的是仿真训练会话，例如开始、暂停、继续和停止；参数策略控制的是导纳参数更新，不是直接操作三关节电机。

### 11.4 Agent 事件的优先级

Agent 有事件冷却时间，避免每个遥测周期重复说同一句话。安全停止和危险类事件优先级高于普通提示。Agent 出错时应只影响反馈，不得中断遥测和安全控制。

## 13. Phase 10：系统实验、图表和视频

### 13.1 配置文件

打开 `configs/phase10.yaml`，重点关注：

```yaml
experiment:
  task: point_to_point
  patient_profiles: [mild, moderate, severe]
```

默认完整矩阵是：


quick 模式默认使用一个 seed、每个条件一个 episode 和很短的 RL 训练步数，目标是验证整条流水线，不是产生论文级结果。

视频是无头 MuJoCo 仿真轨迹，不是真实摄像机录像，也不是人体实验视频。

例如只比较三种经典方法和中度患者：

```bash
python3 -m scripts.run_phase10_experiments \
```

## 16. 常见错误和处理方法

### 错误 1：`No module named rehab_sim`

确认当前目录是工作区根目录，并使用模块方式运行：

```bash
cd rl_admittance_rehab_ws
python3 -m scripts.check_config
```

### 错误 2：没有弹出 MuJoCo 窗口

先检查是否使用了 `--headless`。Phase 4 Gymnasium 环境当前是无头环境，Phase 10 的视频也是离屏生成的。

### 错误 3：RL 训练结果忽好忽坏

强化学习本来具有随机性。增加 seed 数量，保存配置哈希，报告均值和标准差，不要只看一次运行。

### 错误 4：评估结果完全不对

检查是否加载了训练时的 `vecnormalize.pkl`。SAC/PPO 的模型文件和归一化统计必须配套。

### 错误 5：机器人启动后动作过大

先切换固定参数，检查零位和仿真速度/加速度限制；然后检查动作裁剪、参数边界和安全回退。不要通过删除限幅来“解决”问题。

### 错误 6：网页可以打开但没有真实机器人动作

这是当前设计。网页默认使用仿真 provider，ROS2 配置中的硬件开关是关闭的，Agent 也不具有控制权限。

### 错误 7：ROS2 找不到包

```bash
source /opt/ros/humble/setup.bash
colcon build --base-paths ros2_ws --symlink-install
source install/setup.bash
```

然后确认 `ros2 pkg list | grep rehab` 能找到项目包。

## 17. 如何判断一次实验是否可信

至少检查以下项目：

1. `run_metadata.json` 中是否记录了 Git commit、配置哈希和随机种子；
2. 各方法是否使用相同任务和患者集合；
3. 是否记录了足够多的 episode 和多个随机种子；
4. 成功率提升时，峰值交互力是否也变得不可接受；
5. 辅助能量增加时，患者主动功率是否下降；
6. 参数振荡率是否异常；
7. 是否出现不安全终止；
8. 结果是否只是仿真代理指标；
9. 是否避免把“仿真成功”写成“临床有效”；
10. 修改配置后是否重新运行测试。

一个合理的实验结论应该同时描述收益、代价和限制，例如：

```text
某方法在当前虚拟患者和任务上降低了平均跟踪误差，
但辅助能量和峰值交互力也发生变化；该结果仅说明仿真条件下的趋势，
还需要更多随机种子、真实传感器标定和无人体台架验证。
```

## 18. 最后必须记住的安全边界

- 不要让 RL 直接输出关节力矩、电机电流或驱动器命令。
- 不要把仿真 `safety.yaml` 阈值当成真实人体安全阈值。
- 不要因为模型能收敛就跳过急停、限位和通信看门狗测试。
- 不要让 LLM 或 Agent 绕过安全监督器。
- 不要把虚拟患者的主动功率直接解释为临床生理测量。
- 不要把无头 MuJoCo MP4 当成真实机器人演示视频。
- 真实机器人接入前必须重新校准零位、末端工具偏置、力传感器和全部限制。

本项目的正确学习目标是：先掌握可复现的仿真闭环，再逐层理解控制、学习、安全和通信，最后才讨论真实机器人接入。
